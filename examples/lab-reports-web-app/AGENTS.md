# AGENTS.md

Guidance for AI coding agents working with this example. It is a **worked
reference for Terra's Lab Reports API** joined with wearable data: upload a
lab-report PDF, get standardized biomarkers back, and read them against the
same patient's wearable history. The join key is `reference_id` - it is the
only thing connecting a lab upload to a wearable connection; the patient
roster (names, DOBs) is app-owned, Terra stores none of it.

Live API docs: https://docs.tryterra.co (append `.md` to any page for
markdown).

## Run it

```bash
npm install
npm run setup        # env check — names every key and where to get it (exit 0 always)
npm run dev          # ZERO credentials needed: demo mode on bundled sample data
```

- **Demo mode** (no `.env` keys): the server bootstraps `./data/app.db` from
  `db/demo.db` and serves it read-only - four synthetic patients, three years
  of lab history for one, 18 months of wearable data, pre-generated AI
  content. Mutations are blocked behind a visible banner.
- **Live**: put `TERRA_DEV_ID`, `TERRA_API_KEY` in `.env` (see
  `.env.example`), `npm run seed`, then upload the PDFs in `sample-reports/`
  oldest-first (or any real report). Lab Reports must be enabled for the dev
  ID on dashboard.tryterra.co.
- **AI** (optional): `ANTHROPIC_API_KEY` enables live brief regeneration,
  roster-aware chat, and on-demand wearable-signal insights. Without it,
  pre-generated content still renders and generation UI hides.

## Architecture in one pass

- `src/server/index.ts` - Hono route chain; `export type AppType` is the
  whole client contract (consumed via `hc<AppType>`, no codegen). Don't
  break the chain.
- `src/server/lib/terra/` - raw fetch client (lab-reports endpoints are not
  in the terra npm SDK), typed payloads, error mapping.
- `src/server/lib/lab-reports.ts` - session access with a write-through
  cache (terminal sessions are immutable) + computed-flag fallback: when a
  report prints a range but Terra returns `flag: null`, the flag is derived
  and marked `source: "computed"`.
- `src/server/lib/wearables.ts` - userInfo fan-out, per-day cache, 28-day
  chunked fetches (sequential; provider rate limits get paced retries with
  partial progress kept), multi-provider first-non-null merge, full-history
  discovery by probing backward. `demo:<referenceId>` users are cache-only.
- `src/server/lib/analysis/` - deterministic scoring: `domains.ts` is the
  single registry (biomarker keys, weights, guideline bands); `lab-history.ts`
  adds chronicity/trajectory/baseline per biomarker. Change scoring here.
- `src/server/lib/ai.ts`, `flag-insight.ts`, `chat.ts` - Claude via the
  Anthropic SDK; flag insights use structured output (`messages.parse` +
  `zodOutputFormat`). Content is cached in the `ai_report` table by input
  hash; without a key the newest cached content is served instead.
- `src/client/` - React 19 + TanStack Router (file-based) / Query. Server
  types flow through `src/client/lib/queries.ts`.

## Conventions that matter

- Never drop unmatched results (`biomarker.key === null`) - render them
  verbatim; that is the "not standardized" signal.
- Every AI claim is hedged and every chart next to AI text is computed from
  real series - keep it that way.
- No arrow characters or em dashes in user-visible text or AI prompts;
  plain hyphens and comma lists.
- `sample-reports/` PDFs are generated by
  `scripts/generate-sample-reports.mjs` and are entirely fictional - keep
  the synthetic-data footer if you regenerate them, and never commit real
  patient data or a database containing it (`data/` is gitignored for that
  reason).
