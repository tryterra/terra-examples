**Demonstrates:** lab-report upload and standardization (PDF to canonical
biomarkers with ranges, flags and provenance), cross-report biomarker trends
joined by `biomarker.key`, the lab x wearable join via `reference_id`, a
patient timeline of lab draws over wearable lanes, deterministic domain
scoring with an explainable "Why this score" table, chronicity and trajectory
assessment against each patient's own baseline, pre-draw context (recent
exertion and sleep next to each report), AI wearable-signal insights with
structured output, per-patient watchlists, retest-overdue triage, and a
copy-to-EHR chart note.

## Quick start

```bash
npm install
npm run dev
```

That's it - with no credentials the app runs in **demo mode** at
http://localhost:5173: four sample patients with fully synthetic lab reports
(three years of history for one of them), an 18-month wearable dataset, and
pre-generated AI insights. Mutating actions are disabled behind a visible
banner.

### Go live on the Terra API

1. Copy `.env.example` to `.env` and fill `TERRA_DEV_ID` + `TERRA_API_KEY`
   (from [dashboard.tryterra.co](https://dashboard.tryterra.co)). Make sure
   **Lab Reports** is enabled for your dev ID, plus the wearable data types
   you want (daily, sleep, body, activity).
2. `npm run seed` - creates four demo patients and prints their
   `reference_id`s.
3. `npm run dev` - upload the PDFs in [`sample-reports/`](./sample-reports)
   (entirely synthetic; upload them oldest-first to build trends), or your
   own reports. Connect a real wearable through the in-app **Connect
   wearable** button, or seed synthetic wearable data:
   `npm run seed:wearables -- <referenceId>`.
4. **AI features (optional):** add `ANTHROPIC_API_KEY` to `.env` for the
   live Intelligence Brief, the roster-aware chat, and on-demand
   wearable-signal insights on flagged values. Without it the demo-mode
   content still renders; generation and chat hide themselves.

## What to look at

- **Patient overview** - Intelligence Brief (terse AI chart-note bullets +
  inline chat), flagged lab values with chronicity chips ("Chronic · since
  Sep 2022 · rising") and AI clickdowns that chart the wearable metrics the
  model cites, a per-patient watchlist, the lab-report list, a patient
  timeline (lab draws as events over resting HR / HRV / sleep / training
  lanes), deterministic domain gauges, and wearable snapshot cards.
- **Report detail** - panel-grouped standardized results with range bars,
  flags with provenance (report-printed vs computed), deltas vs the previous
  report, pre-draw context chips (workout on draw day inflates CK and liver
  enzymes; short-sleep weeks skew glucose), and unmatched rows kept verbatim.
- **Lab trends** - any biomarker appearing in two or more reports charts
  across years, matched by its canonical `biomarker.key` across labs,
  languages and formats.
- **Wearable trends** - daily metrics with rolling-average trend overlays,
  lab-draw markers, presets from 7 days to the patient's full history.
- **Roster** - triage-sorted: flagged counts and retest-overdue badges.

## How it's wired

- `reference_id` is the only join key: lab uploads and wearable connections
  both attach to it; the patient roster is app-owned (Terra stores no names).
- Lab sessions are immutable once terminal, so they're cached write-through
  in SQLite; wearable days are cached per (user, resource, day). Demo mode
  is the same read path served cache-only from `db/demo.db`.
- Scores stay deterministic (`src/server/lib/analysis/` - a declarative
  registry of domains, weights and guideline bands). The AI layer narrates
  and selects; every number and chart it appears next to is computed.
- AI output is schema-validated (structured outputs via the Anthropic SDK)
  and cached by input hash, so unchanged data never regenerates or drifts.

## Sample data

Everything in demo mode is synthetic: the PDFs in `sample-reports/` are
generated by `scripts/generate-sample-reports.mjs` (fictional patients and
laboratory, marked as synthetic on every page), and the wearable history
comes from `scripts/seed-wearables.ts`. Regenerate or extend either and
rebuild `db/demo.db` by uploading + browsing once with live credentials.
